在当前文件夹运行：

```powershell
python -m pip install -r requirements.txt

```

也可直接运行 `python server.py --port 8765`，然后访问 http://127.0.0.1:8765/ 。

直接打开 `index.html` 可离线查看图表、操作规则分析、在浏览器保存任务和导出报告。清洗脚本、SQLite 和可选本地模型需要 Python 服务。

## 面试演示

点击右上角「面试演示」开始六步演示，自动开启名称脱敏。按顺序讲述经营问题、广告诊断、库存判断、执行闭环、Skill 运行与项目架构。项目页可下载讲解稿，或使用浏览器打印保存 PDF。

脱敏是工作台显示与导出报告中的名称替换，不会修改源数据。完整工程包仍含真实历史数据，原始模块和原始表格不做假数据替换。不要把完整工程包当作已脱敏的数据包发送给 HR。

## 新增口径

| 分析 | 口径与边界 |
|---|---|
| 广告投入回报 | 收入/成本；成本为零显示空值；按货币分别计算 |
| 广告诊断 | 正消耗 Ineligible 优先核实；消耗 < 5 先观察；其余零订单或 ROI 低于可调目标进入候选；不修改原风险分级 |
| 库存覆盖不足 | 已匹配 ERP、可用库存 > 0、7日均销 > 0、原可售天数 1–14；单位为商品款，不等于原 SKU 风险卡 |
| 达人集中度 | 有收入达人明细中 Top10 GMV/明细总GMV；总览与明细分母分开 |
| 达人退款金额占比 | 退款金额/归因GMV；可能超过100%，不裁剪，不替代订单退款率 |
| 利润观察 | 结算金额−订单成本；未计完整广告、仓储等成本，不作为完整净利润 |
| 退包类型 | 账单记录数，不把重复账单行伪装成唯一订单数 |
| 行动候选 | 广告最多8项、库存最多5项、达人最多4项；按风险与业务指标排序，不是全量风险计数 |

## DeepSeek 真实 AI 分析

默认「按问题回答」：用户问题决定输出范围，不再固定附带经营报告、行动表、三日计划。明确要求完整报告或选择「完整报告」时才按报告需求展开。问题中明确提到的模块优先于上次选中的快捷标签。

例如问 `expose tk的日销哪个产品异常`，自动匹配 `EXPOSE.TK`，只读取该店日销，按商品归集后提供日销量与变化；不会混入其他EXPOSE店铺或广告/达人摘要。名称歧义会提示确认，日期没有数据会直说。日销下滑筛选沿用原导出口径，原看板不修改；日期不足14天的比较基准为首日销量，不伪称完整前7天。

指定广告商品ID/计划/账号、达人名、库存商品/SKU或账单款名时，尝试从完整来源检索实体，而不只取预选风险列表。无法匹配的实体不能用其他实体数据替代。过长输入会明确标记截断范围；不保证任意模糊名称都能自动匹配。

已接入 DeepSeek 官方 Chat Completions 接口，也保留本机模型兼容。只允许官方 `https://api.deepseek.com` 或本机地址，不接受其他外部网关，不跟随重定向。点击「生成 AI 分析」才发送当前范围的证据摘要和问题；不会上传整份 Excel，不会自动执行业务动作。

1. 本机已配置用户提供的 Key，无需再填。不要把 `.env` 分享给 HR 或上传 GitHub。
2. 迁移机器时，复制 `.env.example` 为 `.env`，填写自己的 `WORKBENCH_LLM_API_KEY`。
3. 默认模型 `deepseek-v4-flash`，地址 `https://api.deepseek.com`。本机模型可改为 Ollama 地址及已安装模型名。
4. 启动服务，打开「AI 分析助理」，选择分析范围、填写问题并点击「生成 AI 分析」。调用消耗 API 账户额度，不自动重试。
5. 点击「查看输入证据」可看带编号的摘要；成功报告进入 SQLite 分析历史，可回看、导出，不需重复调用。

模型结果始终标记待复核；计算由既有脚本完成。输入永远来自数据，不会把上一轮生成内容当作新证据。记录模型、时间、Token、输入 SHA256 与完整提示词；不记录 Key。401/402/429/超时等错误会明确提示，不用规则文本冒充 API 回复。模式切换不会改变原 Skill 结果。

接口依据：https://api-docs.deepseek.com/zh-cn/ 。实际数据仍是历史快照；推理和建议不是已证实因果。原账单含部分费用列，新增摘要未包含的字段可回原表核查，不应直接称全部费用数据缺失。面试脱敏仅是显示层，工程包仍含原始内嵌数据，不宜直接公开。

## 本地数据与日志

在 D:/codex 中运行时，按项目约定保存：

- `data/raw/ai_workbench/<job>/`：清洗输入原表。
- `data/output/ai_workbench/<job>/`：原清洗 Excel 与运行日志。
- `data/processed/ai_workbench/workbench.sqlite3`：待办状态、AI 历史报告与输入证据。
- `logs/ai_workbench.log`：本地 API 访问、清洗与模型任务日志（不记录密钥和模型提示词）。

独立解压后，则在解压目录下的 data/ 与 logs/ 保存。报告和浏览器导出的 Excel 在浏览器下载目录。
