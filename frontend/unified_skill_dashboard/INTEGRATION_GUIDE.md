# 商策 v3.1 · 商品运营与原 Skill 工作台

## 启动与当前边界

需要 Python 3.11+、Node.js 20+（本机已使用 Node 24 验证），执行 `启动综合看板.ps1`。
访问 http://127.0.0.1:8765/ 。服务仅绑定回环地址，不部署公网。
原 HTML/Skill 字节保留；新增适配器负责共享数据、上传、周期标签和持久化。
完整模块仍使用隔离渲染容器以避免原脚本全局变量冲突，但不再拥有各自独立的导入数据：都读取同一 SQLite 版本。

## 一次导入的日常流程

1. 「数据与 Skill」批量选择 XLSX/XLS/CSV。所有工作表均预检，不只读取首表。
2. 检查识别类型、表头位置、行数与样例；勾选需要激活的表，填写实际业务周期和币种。
3. 查看「预览导入影响」，确认将新增或修订的范围。日销、广告、已处理账单可选「按店铺 / 周期更新」；ERP、产品包等共享表仍选「整体替换」。未选中类型保留原数据和真实周期。
4. 数据、日志、原文件及历史版本落地本机。重复同批内容不累计；版本冲突会要求刷新。
5. 广告、日销库存、售后、利润、达人等模块读取新版本。历史广告可勾选同币种历史快照做周度比较。
6. 行动中心「同步候选」使用服务端完整数据，保留同对象同规则的任务，不按首页显示条数截断。

日销候选按每个店铺独立执行原下降汇总规则；例如历史 EXPOSE.TK 的71款下滑商品均可进入候选，不只包含首页前几款。它们只是待核查项，不代表已证实的异常原因。可在任务中定位同版本原始日销、人工确认并上传真实证据。

### 分区更新的明确语义

- 同店铺、同周期、同币种：修订该分区；其他店铺同周期数据保留。
- 新周期或其他币种：独立保存，切换当前分析范围；不与旧周期、其他币种一起合计。可在数据中心切回任一已保存周期。
- 同类型本次多文件仍须为同周期、同币种；每个选中店铺需提供该周期完整报表，不是随意追加几行订单。
- 同内容重复导入不累计；影响预览不激活，不修改当前版本。
- 原日销历史有1行店铺未标注，按原值保存在历史未标注分区。历史广告没有原始店铺列，不能凭商品名猜店铺。
- 历史同周期存在未标注店铺时，无法证明新数据不与它重叠，因此阻止该周期的店铺分区合并。请核对完整原表后整体替换，或导入独立新周期。
- 手动选择整体替换时，该类型当前分区目录将重建；之前分区仍可从旧数据版本恢复。
- 日销所填周期必须与实际日期列起止相符，不允许给旧数据改标签冒充新数据。

## 商品与异常工作区

从左侧「商品与异常」进入。以当前日销覆盖的店铺商品为入口，不冒充所有平台的完整商品主档。

1. 数据健康：检查缺日期、空销量、非数值、重复SKU、ERP未匹配及原批次完整度。提示不自动改写原数据；末日是否全天仍需人工核查。
2. 异常分诊：保留原下降汇总全部集合。新增排序依次为末日减少件数、连续下降天数、近7日日均销量，明确展示质量提示；没有黑盒AI评分。
3. 商品档案：精确店铺/款名日销、精确SKU仓库库存、人工确认的商品ID映射及可关联的账单/售后明细。未关联、映射冲突和不同周期分别说明。
4. 图表与证据：日销折线及实际事项日期标记；页面每块最多100行，下载商品证据JSON包含各块完整匹配行。新档案导出不替代原Skill格式导出。
5. 人工反馈：正常波动、数据问题或继续核查，必须填写依据，按数据版本留档，不改变原规则或自动屏蔽下批异常。
6. 观察时间线：记录实际核查、促销、调价、库存等事项和行动历史。记录不执行平台操作；不能把尚未发生的计划记为实际事项。
7. AI：商品档案可携带对象和周期起草问题；工具回答中的日销商品可直接打开档案。新增只读商品档案与健康检查工具，按钮「新对话」清除当前追问上下文但不删除历史。

原日销完整模块的商品详情顶部也提供店铺选择和商品全景入口；原详情函数和计算保留。

数据中心列出各流程需要的全部表头。未识别、不完整、长数字 ID 已损坏的表不可激活。
导入支持固定规范和原页面已有别名，不会用模型猜字段含义。

## 原流水线

- GMV 清洗：广告素材文件 + 人员名单 + 明确 L7D 起点，仍执行原 Python 文件。结束日期和币种用于版本元数据，不改变原 `Time posted >= 起点` 筛选；结果固定15列、CTR/CVR算术平均百分点显示。清洗结果进入数据中心，不替代素材明细。
- 马帮→账单→利润：按 `MSxxxx马帮.xlsx`、`MSxxxx账单.xlsx` 命名，另上传产品包。产品包需带 SKU 与销售成本国家币。后台直接执行原 HTML 中的 `SKILL_PIPE.stage1/2/3`，不重新编造算法。
- 三阶段原输出独立保留；用于看板的账单视图沿用原页面的27列映射。两者各自导出，不把标准化视图冒充原阶段输出。
- 利润多店导出保留原「利润汇总(全部) / 店编维度(全部) / 产品维度(全部) / 产品标签(全部)」结构及百分比格式。
- 新账单导入或切换账单分区会使旧流水线缓存退出当前视图；利润导出按当前账单重新计算，旧三阶段输出保留在旧数据版本。运行新流水线时重建账单全表及当前目录，不将旧账单分区误标为新处理结果。
- 缺产品包会阻止流水线运行；有产品包但部分 SKU 不匹配时，保留原脚本行为并醒目标明未匹配数量，不声称这些成本准确。

## AI 与行动闭环

AI 使用 DeepSeek 官方工具调用：查数据集、分页查完整数据、按原口径查日销异常、调用原利润计算、读取人工映射、核对跨表周期。
问题决定回答内容，不强制附运营报告。当前对话支持连续追问；每轮重新固定数据版本，历史回复不替代新查数。
每次结果保存工具参数、返回值、数据版本、模型和 Token；页面可展开「本次查数依据」，历史可查原输入。
只有具体问题所需的业务证据会发送模型服务；密钥不发送浏览器、不打包、不写日志。

任务的原始证据、执行方案及验收仍需人审。可上传图片、PDF、表格或文本证据；按文件 SHA-256 留档。
新版本与执行基线不一致时，只给观察或「待验证」，不自动声称有效、不自动完成任务。
已归档记录不静默改写；历史 AI 调用和状态日志保留。系统不退款、不调价、不投广告、不发送客户消息。

## 保留原值与已知限制

- 原日销 HTML 的内嵌冻结值与自身实际运行结果存在229处字段差异，主要是舍入和列表顺序。原值另存 `embedded_daily_baseline`；新工作台与完整模块统一采用原函数实际运行结果。数据中心可查每处差异。
- 原售后汇总无历史逐单原表，不能还原订单；新原表可上传。当前单批最多4个月，月份轴根据实际输入适配，不延用5—8月标签。
- 现有历史广告、日销库存、账单和达人周期不同，不做跨期拼接归因。跨表工具需要唯一人工确认映射和一致观察窗口，否则明确返回不可比原因。
- 广告板块四个脚本及49列规范缺失，相关流水线未接通；仅保留现有说明、输入预检和结果原值。
- TikTok、马帮官方 API 仅预留只读接口，状态是「未配置」，不模拟同步成功，不做浏览器登录自动化。
- 原营销旧页的占位功能没有凭空变成平台数据。功能清单区分接入、测试及资料缺口，不以整页能打开代替所有控件验收。
- 演示脱敏只覆盖简明工作台；完整模块、数据中心与工程包含业务原值。不要把完整工程包当作脱敏材料外发。

## 扩展接口

- `/api/hub/imports/preview`、`/imports/{id}/activate`：预检与原子激活。
- `/api/hub/workspace`、`/versions`、`/versions/{id}/restore`：版本读取和恢复。
- `/api/hub/query`、`/linked-product`、`/mappings`：受控查数和人工映射。
- `/api/hub/pipeline/run`、`/pipeline/export/{stage}`：原三阶段处理与导出。
- `/api/hub/assistant`、`/assistant/stream`：独立聊天上下文、流式回复与按需只读查数。
- `/api/hub/conversations`：聊天搜索、保存、重命名、导出及可恢复回收站；详见 `CHAT_GUIDE.md`。
- `/api/hub/actions/{id}/attachments`、`/comparison`：证据留档与观察比较。
- `/api/hub/connectors`、`/connectors/{id}/check`、`/pull`：TikTok/马帮只读连接器扩展点，未配置返回503。

旧 `/api/analyze`、任务及行动接口保留兼容。正式工作台通过 `use_workspace=true` 同步服务端候选；旧客户端不改变原接口语义。
