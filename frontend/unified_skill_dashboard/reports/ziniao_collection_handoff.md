## 使用入口

工作台 → 数据中心 → 紫鸟自动采集。当前本机入口 http://127.0.0.1:8765/#data 。不公开公网。

1. 打开首批任务「详情 / 处理」，核对店铺、2026-09-04～2026-09-10、MYR、表头、订单数及金额；原文件可直接下载。
2. 确认后点击「核对并导入，生成 AI 报告」。此步骤会激活一个新工作台版本，并可能调用现有 DeepSeek 配置。首批未确认前，旧工作台数据不变。
3. 生成报告后打开「报告与追问」。聊天固定引用该批次，既可继续提问，也可通过既有按钮编辑建议并加入行动中心。任务详情可返回原聊天、查看本批原生明细。
4. 首批核对后，再单独点击「启用定时」。默认每天马来西亚时间 09:00，当月 1 日至当天的账单。需要工作台后台和紫鸟运行，不需要保持工作台页面打开，不安装开机启动。

## 实现边界

- 只使用官方 CLI 复用本机授权；固定店铺 ID + 页面实际身份双校验，不允许模型传命令/SQL/选择器。
- 原有马帮、利润和旧 Skill 算法不变。新数据位于版本的 `tiktok_native`，重叠采集窗口按快照修订替代，不相加；旧快照可追溯。
- 原文件不可覆盖，识别准确的本次导出记录后才归档；下载中断、身份、表头、日期、唯一键或汇总不一致均暂停。
- 首批或配方变化需重新审核。空文件默认暂停，不用空报表代替失败；需得到平台零记录证据后才能审核放开。
- 历史订单数据的取消商品行筛查仍保留：取消行至少 5 且占比至少 20%。新账单单表批次不执行此订单筛查。
- 自动 AI 每店每天最多一次；输入 UTF-8 字节保守限制与输出 max_tokens=2000，不保证固定金额。失败不自动付费重试，手动重试需再次确认。原文件里的买家姓名/电话/地址/备注不进入 AI 字段白名单。
- 进程中断的 AI 请求先标为结果不确定；十分钟内不重复调用，超过后仍需人工确认重试。任务可查 ai_attempts 审计记录。
- 离线错过 09:00 的计划只记录未执行，重启不积压补跑。暂未支持任意历史日期自动补跑，手动新建任务同样采用当月 1 日至当天。
- TikTok 和马帮官方 API 连接器保持未配置；这里是浏览器报表导出，不冒充官方 API。
