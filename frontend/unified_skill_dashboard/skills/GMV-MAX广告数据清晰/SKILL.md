# GMV MAX 广告数据清洗汇总

## 概述

本技能用于将多家 TikTok GMV MAX 店铺的广告数据（Excel/CSV）清洗并汇总为一张表格。每家店铺的广告数据文件以店编命名，配合一份店铺人员对应名单，最终输出包含人员信息、L7D指标、总量指标的汇总表。

## 适用场景

- **适用**：TikTok GMV MAX 广告数据清洗汇总（多家店铺批量处理）
- **不适用**：广告策略分析、投放优化建议

## 输入要求

### 输入1：广告数据文件

- 多家店铺的广告数据表格，文件名以店编命名（如 `Shop001.xlsx`、`Shop002.csv`）
- 支持 `.xlsx`、`.xls`、`.csv` 格式
- 可放在同一目录下批量处理，也可逐个指定文件路径
- 数据表需包含以下核心列（支持中英文列名变体自动匹配）：

| 列名（TikTok导出原文） | 用途 | 别名兼容 |
|---|---|---|
| Cost | 广告消耗 | Spend / 广告消耗 / 消耗 / Advertising cost |
| Creative type | 素材类型分类 | Creative Type / 素材类型 / Ad type |
| Time posted | 发布时间，用于L7D筛选 | Time Posted / 发布时间 / 创建时间 / Creation time |
| Product ad click rate | 点击率CTR | CTR / 点击率 / Click-through rate / 广告点击率 |
| Ad conversion rate | 转化率CVR | CVR / 转化率 / Conversion rate / 广告转化率 |

### 输入2：店铺人员对应名单

- 表格格式，表头：`店名 | 店编 | 国家 | 初级 | 中级 | 储高/见高 | CEO`
- 支持 Excel/CSV 格式

## 工作流程

### 步骤1：确认输入与 L7D 起始日期

1. 确认广告数据文件位置（目录路径或文件列表，文件名以店编命名，如 `SHOP001.xlsx`）
2. 确认人员名单文件路径（表头：`店名 | 店编 | 国家 | 初级 | 中级 | 储高/见高 | CEO`）
3. **必须向用户询问 L7D 起始日期**（这是本技能的固定前置步骤）：
   - 直接问用户："本次导出的数据是从几号到几号？L7D（近7天新建素材）从几号起算？"
   - 用户给出的导出起始日即为 L7D 起点（例：导出 7.1–7.14，则 L7D 从 7.1 起算；Time posted ≥ 该日期的素材计入 L7D）
   - 拿到日期后，将其作为 `--start-date YYYY-MM-DD` 传给脚本
   - 仅在用户明确要求"自动推断"时，脚本才以数据中最大发布日期前推 6 天作兜底；默认应先询问，不要自行猜测

### 步骤2：执行清洗汇总脚本

运行 `scripts/gmv_max_cleaner.py`，该脚本会自动完成以下全部清洗步骤：

1. **读取人员名单** — 解析店名/店编/国家/人员信息
2. **匹配文件与店铺** — 通过文件名中的店编匹配人员名单
3. **剔除Cost=0的行** — 移除所有广告消耗为0的素材/商品卡
4. **统计素材类型分布** — 通过 Creative type 列统计商品卡/视频素材条数
5. **筛选L7D新建素材** — 通过 Time posted 筛选近7天新建的素材
6. **计算CTR/CVR** — 分别计算总体平均CTR/CVR和L7D新建素材的平均CTR/CVR
7. **合并人员信息** — 将店铺人员信息拼接到汇总结果中
8. **输出汇总表** — 生成格式化的 Excel 文件

#### 运行命令

```bash
# 方式1：指定广告数据目录（推荐，批量处理）
python scripts/gmv_max_cleaner.py --ad-dir <广告数据目录> --mapping <人员名单文件> --start-date 2024-07-01 --output <输出文件路径>

# 方式2：指定具体文件列表
python scripts/gmv_max_cleaner.py --ad-files <文件1> <文件2> ... --mapping <人员名单文件> --start-date 2024-07-01 --output <输出文件路径>

# 方式3：不指定日期（自动检测L7D起始日期）
python scripts/gmv_max_cleaner.py --ad-dir <广告数据目录> --mapping <人员名单文件>
```

**参数说明：**

| 参数 | 必填 | 说明 |
|---|---|---|
| `--ad-dir` 或 `--ad-files` | 是（二选一） | 广告数据目录 或 文件路径列表 |
| `--mapping` | 是 | 店铺人员对应名单文件路径 |
| `--start-date` | 否 | L7D起始日期，格式 YYYY-MM-DD。不指定则自动检测 |
| `--output` | 否 | 输出文件路径，默认 `GMV_MAX_汇总结果.xlsx` |

### 步骤3：检查输出

脚本运行后会在终端输出每个店铺的处理日志和最终汇总预览，同时生成格式化的 Excel 文件。

## 输出格式

### 汇总表表头

```
店名 | 店编 | 国家 | 初级 | 中级 | 储高/见高 | CEO | L7D新建素材数 | L7D新建素材消耗额 | 总素材数 | 总消耗 | L7D CTR | L7D CVR | 总CTR | 总CVR
```

### 列说明

| 列名 | 说明 |
|---|---|
| 店名 ~ CEO | 来自人员名单的人员信息 |
| L7D新建素材数 | 近7天（Time posted >= 起始日期）的素材条数 |
| L7D新建素材消耗额 | 近7天新建素材的Cost汇总（已剔除Cost=0） |
| 总素材数 | 剔除Cost=0后的全部素材条数 |
| 总消耗 | 剔除Cost=0后的全部素材Cost汇总 |
| L7D CTR | 近7天新建素材的平均 Product ad click rate（%） |
| L7D CVR | 近7天新建素材的平均 Ad conversion rate（%） |
| 总CTR | 全部素材的平均 Product ad click rate（%） |
| 总CVR | 全部素材的平均 Ad conversion rate（%） |

### 输出文件特征

- Excel 格式（`.xlsx`），带蓝色表头、边框、居中对齐、冻结首行、自动列宽
- 若某店铺在名单中但无数据文件，仍保留该行（指标为0）
- 若某数据文件无法匹配名单中的店编，人员信息为空但仍汇总广告指标

## 注意事项

- **列名兼容**：脚本内置中英文列名别名表，可自动匹配 TikTok 导出的不同列名变体。若匹配失败，终端会输出警告
- **表头偏移**：TikTok 导出的 Excel 可能前几行是元数据，脚本会自动检测并修正表头行
- **合计行**：脚本自动移除文件末尾的"Total/总计/合计"行
- **CTR/CVR 格式**：输出表内 `L7D CTR` / `L7D CVR` / `总CTR` / `总CVR` 四列的值均为**百分比数值（百分点，如 3.25）并保留两位小数**，单元格数字格式设为 `0.00"%"` 后显示为 `3.25%`。该列是真实数字（可在 Excel 中排序、制图、二次计算）。计算方式为对 `Product ad click rate` / `Ad conversion rate` 列求算术平均（已先剔除 Cost=0），再 ×100 得到百分比数值。输入值自动识别：带 `%` 的字符串（如 `5.23%`）或 `>1` 的数值按百分比解析，`≤1` 的数值按小数解析
- **创意类型统计**：步骤2 通过 `Creative type` 统计商品卡 / 视频素材条数，输出在运行日志中供核对；因固定表头不含该列，故不写入汇总表
- **Cost=0剔除**：在计算所有指标前先剔除，确保 CTR/CVR 均值不受零消耗素材干扰
- **日期解析**：支持多种日期格式（YYYY-MM-DD、DD/MM/YYYY、YYYY年MM月DD日等）
- **百分比解析**：CTR/CVR 支持 "5.23%" 字符串和 5.23 浮点数两种格式
- **智能文件过滤**：自动排除临时文件（`~$`开头）、人员名单文件、输出文件自身；对目录中不含 Cost 和 Time posted 列的文件自动跳过，不误处理
